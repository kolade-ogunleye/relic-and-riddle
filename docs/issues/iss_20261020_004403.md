## User Critique
Why is the review command running without a topic number provided?

## Antigravity (AGY) Autonomous Diagnosis & Resolution
1. **Diagnosis**:
   - In `src/control.py`, when `/review` was invoked without an argument, it previously fell back to auto-discovering the first unreviewed topic and immediately dispatching its storyboard contact sheet.
   - This violated the principle of explicit operator agency: commands should never execute on an assumed topic behind the operator's back when no topic number was provided.
2. **Resolution**:
   - Updated `src/control.py`:
     - When `/review` (or `/storyboard`) is invoked with empty arguments, it no longer executes any topic automatically.
     - Instead, it checks the topic queue and renders an explicit touch selection menu (`🎬 Review #1...`, `🎬 Review #2...`), along with a tap-to-copy command template:
       ```
       🎬 <b><u>Storyboard Review Command Template</u>:</b>
       <code>──────────────</code>
       Tap to copy & edit: <code>/review 1</code>
       Usage: <code>/review &lt;topic_number_or_id&gt;</code>
       ```
     - Tapping any topic button explicitly passes the number (`review:1`), which runs the review for that specific topic.
   - Updated `tests/test_control.py` to assert that `/review` without arguments does not run an arbitrary topic.
3. **Verification**:
   - All 59 tests in test suites pass with 100% success rate.
