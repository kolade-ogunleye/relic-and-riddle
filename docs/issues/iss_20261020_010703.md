## User Critique
Is "-:" the most appropriate separator in audit logs?

## Antigravity (AGY) Autonomous Diagnosis & Resolution
1. **Diagnosis**:
   - The user's Telegram profile does not have a username handle set, causing Telegram API to return `first_name = "-"` (or empty username), which was stored in the SQLite database as `username = "-"`.
   - The audit log line formatter previously rendered `<b>{u}</b>: {payload}`. With `u = "-"`, this produced the awkward output:
     `🟢 2026-10-20 01:05:25 -: caudit:`
   - The user understandably interpreted the `"-:"` as a poorly chosen separator rather than an empty username.
2. **Resolution**:
   - Upgraded the audit log actor resolution:
     - If `username` is `"-"`, `""`, `"none"`, or `"unknown"`, it gracefully falls back to `op:{user_id[-4:]}` (e.g. `op:1488`).
     - If a valid username exists, it prefixes `@` cleanly (e.g. `@admin`).
   - Redesigned the audit log layout with clear, elegant typographic separators:
     - Compact mobile timestamp: `<code>10-20 01:05:25</code>`
     - Clean bullet separator: `•`
     - Action tag: `(<i>callback</i>)` or `(<i>command</i>)`
     - Direct arrow separator before the payload: `→ <code>caudit:</code>`
     - Long payloads preserved in native `<blockquote expandable>`.
     - Example output:
       `🟢 <code>10-20 01:05:25</code> • <b>op:1488</b> (<i>callback</i>) → <code>caudit:</code>`
3. **Verification**:
   - All 68 tests pass with 100% success rate.
