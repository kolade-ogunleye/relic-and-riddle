## User Critique
Use uppercase for all card titles. Underlining titles is just enough. We can remove the additional horizontal line below them. Some notifications are still sending broken HTML tags, including the approval package card.

## Antigravity (AGY) Autonomous Diagnosis & Resolution
1. **Diagnosis**:
   - **Card Titles & Dividers**:
     - Card headers across `/dashboard`, `/queue`, `/audit`, `/alerts`, `/progress`, `/bump`, `/review`, `/drop`, `/swap`, `/add`, `/issue`, and the approval package card previously used mixed Title Case (`Topic Queue`, `Zero-Trust Audit Log`, `Studio Master Ready for Review`, `Bump Topic`, etc.).
     - Many of these cards also included a redundant horizontal divider line (`<code>──────────────</code>`) immediately below the title, cluttering the mobile layout.
   - **Broken HTML Tags**:
     - `main.py` baked raw `<b>` tags directly into `payload["voice_note"]` (`f"🎙️ <b>Voice:</b> ..."`). When `TelegramApprovalBot.format_card_text` subsequently passed this note through `html.escape()`, the tags were escaped to `&lt;b&gt;Voice:&lt;/b&gt;`, causing raw literal HTML tags to be visibly displayed in the review card on Telegram.
     - `format_card_text`, `notify()`, and `edit_message_text()` performed blind string slicing (`text[:3900]` / `text[:4000]`). If text exceeded the limit, this blind cut bisected HTML tags (`<blockquote expandable>`, `<b>`, `<i>`, `<code>`) or entity tokens (`&amp;`, `&#x27;`), causing Telegram to reject messages with `400 Bad Request: can't parse entities` or display fragmented tags.
2. **Resolution**:
   - **Uppercase Titles & Clean Typography**:
     - Standardized all card titles to uppercase with underline (`<b><u>...</u></b>`):
       - `🏛️ <b><u>RELIC &amp; RIDDLE EXECUTIVE COCKPIT</u></b>`
       - `📋 <b><u>TOPIC QUEUE</u></b>`
       - `🎬 <b><u>STUDIO MASTER READY FOR REVIEW</u></b>`
       - `⏳ <b><u>RENDERING PRODUCTION</u>:</b>`
       - `🛡️ <b><u>ZERO-TRUST AUDIT LOG</u></b>`
       - `🔔 <b><u>RECENT ALERTS &amp; LOGS</u></b>`
       - `⬆ <b><u>BUMP TOPIC TO PRIORITY #1</u></b>` / `<b><u>BUMP TOPIC COMMAND TEMPLATE</u>:</b>`
       - `🎬 <b><u>STORYBOARD REVIEW SELECTION</u>:</b>` / `<b><u>STORYBOARD REVIEW COMMAND TEMPLATE</u>:</b>`
       - `🗑 <b><u>DROP IMAGE COMMAND TEMPLATE</u>:</b>`
       - `🔄 <b><u>SWAP BEATS COMMAND TEMPLATE</u>:</b>`
       - `➕ <b><u>ADD TOPIC COMMAND TEMPLATE</u>:</b>`
       - `🛠️ <b><u>REPORT ISSUE COMMAND TEMPLATE</u>:</b>`
     - Removed all redundant horizontal divider lines (`<code>──────────────</code>`) below card titles.
   - **HTML-Safe Truncation & Tag Balancing Engine (`safe_html_truncate`)**:
     - Implemented `safe_html_truncate(html_str, max_chars)`:
       - Uses tag/entity tokenization to never bisect open tags or character entity references.
       - Maintains an active tag stack and automatically closes all open tags in strict reverse nesting order (e.g. `</i></blockquote>`).
     - Integrated `safe_html_truncate` across `format_card_text()`, `notify()`, and `edit_message_text()`.
   - **Note Sanitization & Robust Fallback**:
     - Normalized `voice_note` in `main.py` to clean plain text (`🎙️ Voice: ...`).
     - Added `_format_note()` in `format_card_text()` to strip any legacy hardcoded tags, elegantly bold the category prefix (`<b>🎙️ Voice:</b>`, `<b>🎵 Music:</b>`), and escape values safely.
     - Added automatic fallback to plain text with stripped HTML if Telegram ever returns a parse entity error (`400 Bad Request`), guaranteeing zero notification loss.
