## User Critique
Fix Veo motion requests are missing a required image-format field (HTTP 400) and Changing a topic's priority invalidates its verified script.

## Antigravity (AGY) Autonomous Diagnosis & Resolution
1. **Diagnosis**:
   - **Veo HTTP 400 (Missing Image Format)**:
     - In `src/motion.py`, the `animate_veo()` function constructed an `image` payload containing only `{"bytesBase64Encoded": ...}`.
     - The Google Veo `predictLongRunning` Image-to-Video API explicitly enforces that every input image instance must supply both `bytesBase64Encoded` and `mimeType` (`"image/jpeg"`). Without `mimeType`, Google API rejected motion synthesis requests with `HTTP 400: Input instance with image should contain both bytesBase64Encoded and mimeType`.
   - **Verified Script Invalidation on Topic Priority Change**:
     - In `src/checkpoints.py`, the `topic_inputs(topic)` helper excluded operational state such as `status`, `times_published`, `last_published_at`, `last_run_id`, and `updated_at`.
     - However, `"priority"` was omitted from the operational state exclusion list.
     - When an operator adjusted a topic's queue rank using `/bump <topic_id>` or bumped its priority, `topic["priority"]` changed. Because `priority` was included in the research/script input hash, `checkpoints.reusable("script", script_inputs)` evaluated to `False`. This erroneously treated the verified script as invalid, causing the pipeline to needlessly re-synthesize and re-verify the script from scratch, wasting LLM quota and disregarding the vetted script.
     - In `src/db.py`, `bump_topic()` unconditionally set `status = 'queued'`, which could inadvertently reset in-flight or script-ready topics.
2. **Resolution**:
   - **Veo Payload Hardening (`src/motion.py`)**:
     - Added `"mimeType": "image/jpeg"` to the image instance payload in `animate_veo()`.
     - Verified in `tests/test_motion.py` that both `bytesBase64Encoded` and `mimeType` are correctly formatted in the API dispatch payload.
   - **Checkpoint Operational State Isolation (`src/checkpoints.py` & `src/db.py`)**:
     - Added `"priority"` to the `operational` set in `topic_inputs()`, ensuring queue priority adjustments never alter the cryptographic hash of research inputs or invalidate verified scripts.
     - Updated `bump_topic()` in `src/db.py` to only transition status to `'queued'` if the topic was previously `archived`, `rejected`, or `failed`, preserving existing active states.
     - Added unit test `test_topic_priority_does_not_invalidate_script_checkpoint` in `tests/test_checkpoints.py` to assert that bumping priority preserves reusable script checkpoints.
3. **Verification**:
   - All 79 tests across the full test suite (`test_motion.py`, `test_checkpoints.py`, `test_control.py`, `test_music.py`, `test_ui_overhaul.py`, `test_db.py`) pass with 100% success rate.
